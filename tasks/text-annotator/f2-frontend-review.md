- **[P1] `apps/text-annotator/public/app.js` — stale save response can replace another document’s annotations.** `saveAnnotationList` sends to the current document, then later does `currentAnnotations = result.annotations;` without checking which document is open. If the user opens another document while the PUT is pending, the old response is rendered against the new document; a later save there can persist the wrong list. Capture the document ID when starting the save and ignore the response for the active view if that ID no longer matches.

- **[P2] `apps/text-annotator/public/index.html` — keyboard users cannot create annotations.** The viewer is `<div id="viewer" ... tabindex="0">`, but it is not editable and there is no keyboard range-selection control. Giving a text container `tabindex` alone does not provide caret-based text selection in normal browser keyboard navigation. Add a keyboard-operable way to select a text range and choose its label.

- **[P2] `apps/text-annotator/public/app.js` — oversized files are read before the size limit is enforced.** `const body = await file.arrayBuffer();` runs without checking `file.size`, so a file above the 25 MiB contract limit is fully allocated and sent before the server rejects it. Check against `25 * 1024 * 1024` before reading and show the too-large error immediately.

- **[P2] `apps/text-annotator/public/app.js` — upload can report success when opening failed.** `uploadFile` calls `await openDocument(...)` and then reports “Uploaded and opened…”. `openDocument` catches its own errors and returns normally, so a failed document or annotation GET is followed by a success status. Make `openDocument` return success or rethrow, and only report “opened” when it succeeds.

- **[P2] `apps/text-annotator/public/app.js` — malformed annotation entries can break rendering.** The code accepts any array via `currentAnnotations = Array.isArray(annotationResult?.annotations) ? annotationResult.annotations : [];`, but `renderViewer` sorts entries with `a.start` and `a.end`. A response such as `{ "annotations": [null] }` throws during rendering. Validate each entry’s shape and bounds before committing the response, and report invalid data clearly.

- **[P2] `apps/text-annotator/public/app.js` — mutation controls silently ignore clicks while saving.** Delete buttons remain enabled, but their handler contains `if (saving) return;`. During a save, a user can activate Delete and receive no feedback or action. Disable mutation controls for every save operation and re-enable them in `finally`, or provide an explicit busy response.

- **[P3] `apps/text-annotator/public/app.js` — selecting a mark can scroll to the wrong annotation row.** `selectAnnotation` finds a row by its Delete button’s label, such as `Delete Person annotation`, rather than by annotation ID. With multiple annotations of the same label, it scrolls to the first matching row. Add the annotation ID to the row and match on that ID.
